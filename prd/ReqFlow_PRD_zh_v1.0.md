## 1. 产品概述

### 1.1 产品背景与目标

研发团队在需求管理过程中长期面临需求散落、变更不可追溯、文档与需求脱节、缺乏统一 ID 编号、难以跨项目统计等痛点。ReqFlow 旨在提供一款**本地化、可私有部署、零外部依赖**的需求全生命周期管理工具，覆盖「需求创建 → 变更追溯 → 附件关联 → 文档库 → 多格式导出 → 多项目统计」的完整闭环。

### 1.2 产品定位

面向中小研发团队的需求管理桌面应用 + 可部署 Web 服务。以「轻量、可追溯、可私有化」为核心，数据默认保存在本地（localStorage + IndexedDB），同时支持零依赖 Node 服务器部署，实现团队多人访问与账号注册。

### 1.3 目标用户

- **产品经理 / 需求分析师**：创建、维护需求，规划优先级与截止日期。
- **研发工程师**：查看需求、关联技术文档、按看板流转状态。
- **项目经理 / 团队负责人**：跨项目统计、逾期追踪、导出报告。

### 1.4 核心价值

1. **全生命周期管理**：需求从创建到关闭的完整状态流转与版本追溯。
2. **语义化版本控制**：每次变更自动记录快照，历史可回溯。
3. **全局唯一编号**：`REQ-{分类码}-{序号}` 编号规则，跨项目永不冲突。
4. **文档一体化**：内置文档库与多格式预览，通过 `reqflow://` 链接打通需求与文档。
5. **多格式导出**：Excel / CSV / HTML / Markdown / PDF 一键导出。
6. **可私有部署**：零依赖服务器 + 用户注册登录，数据自主可控。

### 1.5 产品范围

本版（v1.0）覆盖需求管理、版本控制、导出、附件、文档库、预览、部署与账号、统计仪表盘等能力，详见第 5 章详细需求说明。

## 2. 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| 需求（Requirement） | 系统管理的原子实体，含标题、描述、分类、优先级、状态、标签、截止日期等字段。 |
| 需求 ID 号（Code） | 全局唯一业务编号，格式 `REQ-{分类码}-{4位序号}`，如 `REQ-FEA-0001`。 |
| 分类码 | 3 位大写字母，标识需求类别：FEA=功能、BUG=缺陷、OPT=优化、OTH=其他。 |
| 优先级（Priority） | 四级：P0（紧急）、P1（高）、P2（中）、P3（低）。 |
| 状态（Status） | 六态：review（待评审）、todo（待开发）、doing（开发中）、testing（测试中）、done（已完成）、closed（已关闭）。 |
| 语义化版本号 | `vX.Y.Z` 格式，标题变更升 Major、描述/分类变更升 Minor、状态/优先级等升 Patch。 |
| reqflow:// 链接 | 内部文档链接协议，形如 `reqflow://doc/{id}`、`reqflow://file/{id}`，用于在需求与文档间建立关联。 |
| 文档库（Docs） | 内置的 Markdown 文档 + 本地文件管理模块。 |
| IndexedDB | 浏览器本地二进制存储，用于突破 localStorage 5MB 限制存储上传文件。 |

## 4. 详细需求说明

### 模块一：项目管理

#### REQ-FEA-0001 基于项目的需求管理
- **优先级**：P1
- **状态**：已完成
- **功能描述**：支持创建多个项目工作空间，需求按项目隔离；顶部提供项目下拉选择器，切换项目后自动过滤需求；历史需求自动归入默认项目。
- **验收标准**：
  1. 可新建、编辑、删除项目，项目含名称、描述、颜色字段。
  2. 顶部项目下拉切换后，列表/看板/仪表盘均仅显示当前项目的需求。
  3. 旧版无项目归属的需求在启动迁移时自动归入默认项目。

#### REQ-FEA-0013 项目状态仪表盘
- **优先级**：P2
- **状态**：已完成
- **功能描述**：提供所有项目的状态总览，展示每个项目的需求总数、状态分布、逾期数、完成率与优先级分布，支持导出报告（Markdown / HTML / PDF）。
- **验收标准**：
  1. 「所有项目状态」入口可打开总览弹窗，逐项目展示统计卡片。
  2. 完成率进度条、优先级分布图表正确反映数据。
  3. 支持导出状态报告文件。

### 模块二：需求管理

#### REQ-FEA-0004 全局唯一需求 ID 号
- **优先级**：P1
- **状态**：已完成
- **功能描述**：每条需求分配全局唯一 ID 号，格式 `REQ-{分类码}-{序号}`（如 `REQ-FEA-0001`）；分类码区分任务类别；列表与看板展示 ID 号并支持点击复制。
- **验收标准**：
  1. 新需求自动生成符合 `REQ-[A-Z0-9]{2,4}-\d{4,6}` 的编号。
  2. 同一分类码下序号严格递增，跨项目不冲突。
  3. 列表/看板中的 ID 号可点击复制。

#### REQ-OPT-0001 分类独立 ID 序号
- **优先级**：P2
- **状态**：已完成
- **功能描述**：每个分类码独立计数、从 0001 开始（如 `REQ-FEA-0001`），避免跨分类序号混乱；历史 5 位序号仍兼容。
- **验收标准**：
  1. 新建功能需求从 `REQ-FEA-0001` 起按序递增，缺陷从 `REQ-BUG-0001` 独立计数。
  2. 历史 5 位序号（如 `REQ-FEA-00042`）依然被识别为合法 ID。

#### REQ-FEA-0011 需求自动保存
- **优先级**：P1
- **状态**：已完成
- **功能描述**：编辑需求时 1.2 秒防抖自动保存，任何字段或附件变化自动落盘并触发版本变更，避免内容意外丢失。
- **验收标准**：
  1. 编辑字段停止输入 1.2 秒后自动保存，无需手动点击。
  2. 自动保存触发版本变更记录。
  3. 页面刷新后编辑内容不丢失。

#### REQ-FEA-0018 创建者/跟进者字段
- **优先级**：P2
- **状态**：已完成
- **功能描述**：需求新增创建者、跟进者字段，下拉选择系统账号（可为空），默认创建者为当前账户；详情、版本与导出均展示这两项。
- **验收标准**：
  1. 新建需求默认创建者为当前登录账户，可手动修改。
  2. 创建者/跟进者可从账号列表下拉选择，也可留空。
  3. 需求抽屉、版本 diff、导出文件均包含创建者/跟进者。

#### REQ-OPT-0002 需求表单布局优化
- **优先级**：P3
- **状态**：已完成
- **功能描述**：优化需求表单布局，附件拖拽框增高、描述框扩大至 9~18 行、编辑抽屉加宽至 810px，提升编辑体验。
- **验收标准**：
  1. 描述输入框默认 9 行，可扩展至 18 行。
  2. 附件拖拽区最小高度 120px。
  3. 编辑抽屉宽度 810px，长内容可完整展示。

### 模块三：版本控制

#### REQ-FEA-0002 需求语义化版本控制
- **优先级**：P1
- **状态**：已完成
- **功能描述**：需求每次变更自动生成版本快照，采用 `vX.Y.Z` 语义化版本号；标题变更升 Major、描述/分类变更升 Minor、状态/优先级/标签/截止日期升 Patch；提供版本历史时间线可回溯查看。
- **验收标准**：
  1. 标题变更后版本号 Major+1（如 1.0.0 → 2.0.0）。
  2. 描述/分类变更 Minor+1；状态/优先级/标签/截止日期变更 Patch+1。
  3. 版本历史时间线可查看任意历史版本的完整快照，查看时表单为只读。

### 模块四：导出

- **验收标准**：
  1. 五种格式均可导出且内容完整。
  2. 导出内容包含项目名称、版本号、创建者/跟进者。

#### REQ-FEA-0005 单条需求导出
- **优先级**：P2
- **状态**：已完成
- **功能描述**：需求抽屉内提供导出菜单，可将单条需求导出为 Excel/CSV/Markdown/HTML/PDF，文件名以需求 ID 号为前缀。
- **验收标准**：
  1. 抽屉内导出菜单提供五种格式选项。
  2. 导出文件名以 `REQ-{分类码}-{序号}` 开头。

#### REQ-FEA-0008 批量导出
- **优先级**：P2
- **状态**：已完成
- **功能描述**：支持批量选中多条需求一次导出，文件名按「项目名_分类_版本号_日期」规范命名。
- **验收标准**：
  1. 批量选择后可通过操作栏一键导出。
  2. 导出文件名符合命名规范。

### 模块五：附件与文档库

#### REQ-FEA-0006 需求附件功能
- **优先级**：P1
- **状态**：已完成
- **功能描述**：需求可关联参考附件，支持拖拽上传本地文件或从文档库搜索关联；附件变更纳入版本控制；描述支持粘贴 `reqflow://` 链接关联文档。
- **验收标准**：
  1. 可拖拽上传本地文件作为附件，也可从文档库搜索关联。
  2. 附件增删触发版本变更（Minor）。
  3. 描述中的 `reqflow://` 链接可点击打开对应文档/文件。

#### REQ-FEA-0007 文档库增强
- **优先级**：P1
- **状态**：已完成
- **功能描述**：文档库支持 Markdown 文档与本地文件管理；二进制文件存 IndexedDB 突破 localStorage 5MB 限制；支持多格式在线预览与 `reqflow://` 链接协议全局跳转。
- **验收标准**：
  1. 可新建/编辑 Markdown 文档，可上传本地文件。
  2. 大文件（>5MB）可正常存储与读取。
  3. 每个文档/文件可复制 `reqflow://` 链接，全局点击可跳转预览。

#### REQ-FEA-0014 文档库拖拽上传
- **优先级**：P1

  1. 空库时显示大拖拽上传区，拖入文件即上传。
  2. 有文件时列表底部仍可拖拽上传。
  3. 拖入整个文件夹后，目录结构被自动还原为文件夹。

#### REQ-FEA-0015 文档库批量选择删除

## 5. 非功能需求

### 5.1 性能
- 需求列表、看板在 1000 条需求规模下交互流畅（首屏渲染 < 1s）。
- 大文件上传通过 IndexedDB 存储，不受 localStorage 5MB 限制。

### 5.2 安全
- 服务器模式密码采用 scrypt 加盐哈希存储，不明文保存。
- 会话使用 Bearer Token，有效期 7 天。
- 本地模式数据存于用户浏览器，不外传。

### 5.3 兼容性
- 支持 Windows / macOS / Linux 桌面端（Electron）。
- 浏览器端支持现代 Chromium 内核（Chrome / Edge）。

### 5.4 可维护性
- 前端 TypeScript 严格模式，模块化分层（context / services / components / hooks）。
- 核心逻辑（ID 生成、版本控制、拖拽收集、导出）独立为可测试的 service 模块。
- 配套 Vitest 单元测试 + Playwright 冒烟测试。

### 5.5 可用性
